# Rule: JT808

Derived from `docs/business/RAAD_Phase3.4_JT808_Technical_Design_v1.md`.

**Status (ADR-0009, ADR-0010, ADR-0015, ADR-0024, ADR-0025):** the procured hardware
(`LSZ-C5804DG-Q-F`) is confirmed JT/T 808-2019 compliant (ADR-0025, 2026-08-10, superseding
ADR-0009's original non-compliance finding for this hardware) — the rules below describe the
*actual*, current device-plane architecture, not a hypothetical future vendor's. The live,
primary GPS adapter is `services/device-gateway/src/vendors/jt808/` (ADR-0025 §4). **The
confirmed-2019 field-width rework is complete (2026-08-11):** `header.py` decodes `BCD[10]`
terminal phone + a protocol-version byte; `0x0100`/`0x0102` bodies match the confirmed 76-byte/
variable-length 2019 shapes; `0x0200`'s own layout was confirmed byte-for-byte unchanged from
2013 against the supplier spec. `services/device-gateway/src/vendors/lsz/` (the proprietary-
protocol adapter, ADR-0009's original design) is kept, dormant, mirroring exactly the posture
`vendors/jt808/` held before ADR-0025 — real, tested code retained for a scenario where a
specific unit or firmware batch genuinely doesn't speak the confirmed protocol, not deleted.
`0x0102` authentication now has a decided, real, **implemented** credential model
(`Device.auth_key_hash`, platform-minted on `0x0100` success, hashed at rest, verified by hash
comparison on `0x0102` — ADR-0025 §3) — rule #4/#5 below apply in their originally-intended form,
not the identity-only reduction ADR-0015 accepted specifically for the no-credential proprietary
protocol. `DeviceOnline`/`DeviceOffline`/`DeviceAlarmRaised`/`DevicePositionReported`/
`DeviceAuthCodeIssued`/`DeviceCommandResult`/`DeviceResourceListReported` are real, Redis-published
events (ADR-0010) regardless of which adapter is live. **JT/T 1078 video signaling is now
forwarded on this same connection (2026-08-11, ADR-0024 §1/§8, ADR-0025 §5):** `commands/
video_signaling.py` encodes/decodes `0x9101`/`0x9102`/`0x9105`/`0x9205`/`0x9201`/`0x9202`
(downlink) and `0x1205` (uplink); rule #6's own correlation-ID tracking is now real
(`commands/pending_commands.py`/`commands/command_sender.py`), consuming command requests from
the broker via `RedisVideoSignalingConsumer`. **The Business-API-side publisher of those
requests now exists (2026-08-12):** `backend/raad/modules/video/infra/adapters.
Jt1078RelayAdapter` publishes `Jt1078SignalCommandRequested` onto this same `raad:events` stream
once `services/jt1078` confirms a session — see `.claude/rules/jt1078.md`'s own status paragraph
for the full backend → relay → device-gateway flow this closes. **Every field-width, auth-code,
and signaling claim in this paragraph is specification-verified and unit/integration-tested
against synthetic fixtures only** — none of it has been exercised against a real, physical MDVR
yet, and this status paragraph should not be read as claiming otherwise.

1. **This service never writes Business API tables directly.** It only publishes domain events
   (`DevicePositionReported`, `DeviceOnline`, `DeviceOffline`, `DeviceAlarmRaised`, command-result
   events) to the broker.
2. **Vendor dialect variation is isolated in an Anti-Corruption Layer.** A new vendor means a new
   adapter — never a change to the core parser/dispatcher/handlers.
3. **Backfilled data is flagged and time-honest.** Buffered positions (0x0704, late 0x0200) publish
   with their original timestamp and `backfill=true`; live views must only use `event_time ≈ now` so
   stale buffered data never corrupts the live map.
4. **Session state lives in Redis**, keyed by `device_id -> {node, vehicle_id, org_id, last_seen,
   auth_state}` — the shared source of truth enabling sharded, sticky device connections.
5. **Unknown/unauthenticated devices are rejected and audited**, never silently dropped without a
   trace.
6. **Command downlink is correlation-ID tracked** — every platform-issued command (0x9101, 0x9201/
   0x9205, 0x8300, 0x8103, 0x8105) must be traceable back to the requesting use-case and its result.
7. **Connectivity monitoring is heartbeat-driven.** Timeout emits `DeviceOffline`; reconnect emits
   `DeviceOnline` — these feed device-status monitoring and exception workflows directly.
